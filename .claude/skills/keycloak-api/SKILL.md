# Keycloak Admin REST API (keycloak v26)

Generated by `npm run scaffold:service` on 2026-10-16, completed at the users intake and kept
current by every later phase. Facts the pack already owns are linked, not copied
(`.claude/rules/documentation.md`).

## Contract

- Tracked copy: `services/keycloak/openapi.json` (openapi-3.0, 413 operations). Its digest is
  `docs/discovery/keycloak-digest.json`; `npm run contract:digest:live -- --service keycloak` compares
  it with the deployed contract.
- Declared servers: none.
- Departures from the contract: `services/keycloak/docs/contract-notes.md`.

## Environments and writes

The environments where this pack runs, its base URL in each and whether writes are allowed there
are set in qa-config (`api.environments.<env>.packs.keycloak`). One environment, `local`: the
in-memory container, writes allowed, recovery restarts it. The realm `qa` has no listed user at
start; its three service-account users are shared records and never change
([users intake](../../../services/keycloak/docs/features/users.md#test-data)).

## Authentication and actors

Security schemes declared by the contract: none, although every admin operation answers `401`
without a bearer token and `403` to a client without the role it needs (KN-01).

The pack's qa-config entry uses `oauth2_client_credentials` against the realm's own token endpoint,
with the actors `admin` (the default), `viewer` and `no-role`, one service-account client each;
[the pack README](../../../services/keycloak/README.md#running-it) says what each client may do
and where the secrets come from. Tokens last 60 seconds; the performance lane cannot renew one, so
its `--duration` stays under about 40 seconds
([the pack README](../../../services/keycloak/README.md#performance) says what `perf.json` keeps
out). The DAST lane renews it during a scan; its files, scope and the realm value ZAP needs are in
[the pack README](../../../services/keycloak/README.md#dast).

## Data

- Identity fields pseudonymized in evidence: `service.json` `identity_fields`.
- Usernames are unique in a realm, so the builder gives each a prefix and a random suffix:
  `services/keycloak/builders/user-builder.ts`; flow: `services/keycloak/flows/users.ts`. The
  three service-account users are shared and no case writes them, so the pack has no guards.

## Errors

Errors come in three shapes (KN-07): `{"error": "<text>"}` for `401`, `403`, `404` and query
validation; `{"errorMessage": "<text>"}` for a body the server refuses after reading it; and
`{"error": "unknown_error", "error_description": ...}` for a body field of the wrong type. A malformed integer query
parameter answers `404`, not `400` (KN-03). The catalogue is `services/keycloak/error-envelopes.json`
(`error`, `error-message`).

## Verification

A case confirms a write with a follow-up read as `admin` (`GET /users/<USER_ID>`), and a refused
write with a state comparison: `expectSameState` over `USER_FIELDS` in
`services/keycloak/state-models.ts` (`services/keycloak/registry/users.md`).
